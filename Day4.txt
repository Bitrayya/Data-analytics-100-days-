 Day 4 — DML: INSERT, UPDATE, DELETE

 DML — Data Manipulation Language

DML commands are used to insert, update, delete, and manage data stored inside existing database tables. Unlike DDL, DML changes can typically be rolled back if not committed.

| Command | Description |
|---|---|
| `INSERT` | Adds new rows/records of data into a table. e.g. `INSERT INTO Students (ID, Name) VALUES (1, 'Ravi');` |
| `UPDATE` | Modifies existing records by changing one or more column values based on a condition. e.g. `UPDATE Students SET Name='Kumar' WHERE ID=1;` |
| `DELETE` | Removes one or more rows based on a condition, keeping the table structure. Can be rolled back within a transaction. |



 INSERT — Four Approaches

### Approach 1 — Named columns, single/multiple rows
```sql
INSERT INTO table-name (column1, column2, ..., column-n)
VALUES (value1, value2, ..., value-n);
```
```sql
INSERT INTO EMPLOYEES (EMPID, FIRSTNAME, LASTNAME, AGE, DOJ, ADDRESS, DEPT)
VALUES ('E001', 'MALLI', 'ARJUN', 27, '2024-03-20', 'HYD', 'JAVA');
```

Multiple rows in one statement:
```sql
INSERT INTO EMPLOYEES (EMPID, FIRSTNAME, LASTNAME, AGE, DOJ, ADDRESS, DEPT)
VALUES
('E002', 'ARJUN', 'SARKAR', 37, '2022-02-20', 'VJY', 'SALES'),
('E003', 'SAI', 'VARDAN', 22, '2024-03-18', 'HYD', 'PYTHON');
```

 Approach 2 — No column list (values must match table's column order)
```sql
INSERT INTO table-name VALUES (value1, value2, ..., value-n);
```
```sql
INSERT INTO EMPLOYEES VALUES
('E004', 'SUMA', 'SRI', 24, '2025-10-10', 'BNG', 'DEVELOPMENT');

INSERT INTO EMPLOYEES VALUES
('E005', 'MANI', 'SHARMA', 17, '2020-09-09', 'MUMBAI', 'MARKETING'),
('E006', 'MOUNIKA', 'KOPPU', 27, '2019-11-11', 'PUNE', 'FINANCE');
```

 Approach 3 — Only the columns you need (others default to NULL)
```sql
INSERT INTO table-name (particular columns you require)
VALUES (particular values);
```
```sql
INSERT INTO EMPLOYEES (FIRSTNAME, DOJ, LASTNAME, EMPID, ADDRESS)
VALUES ('SAI', '2017-07-07', 'RAM', 'E008', 'VIJAYAWADA');
-- AGE and DEPT are left as NULL
```

 Approach 4 — SET syntax
```sql
INSERT INTO table-name SET column-name = value, column-name = value, ..., column-n = value-n;
```
```sql
INSERT INTO EMPLOYEES SET
EMPID='E010', FIRSTNAME='SUDHEER', LASTNAME='KUMAR', AGE=45,
DOJ='2024-06-01', ADDRESS='KOLKATTA', DEPT='DEVELOPMENT';
```

 UPDATE

Syntax:
```sql
UPDATE table-name SET column-name = value WHERE condition;
```

Fill in a missing last name:
```sql
UPDATE EMPLOYEES SET LASTNAME='KUMAR' WHERE FIRSTNAME='ARUN';
```

Correct an age:
```sql
UPDATE EMPLOYEES SET AGE=47 WHERE EMPID='E008';
```

Update by a non-key condition:
```sql
UPDATE EMPLOYEES SET DEPT='IT' WHERE ADDRESS='VIJAYAWADA';
```

Set a previously-NULL date:
```sql
UPDATE EMPLOYEES SET DOJ='2026-06-27' WHERE EMPID='E009';
```

> Each `UPDATE` only changes the row(s) matching the `WHERE` condition — everything else stays the same. Omitting `WHERE` would update every row in the table.



DELETE

Syntax:
```sql
DELETE FROM table-name WHERE condition;
```

Delete a single row by primary key-like value:
```sql
DELETE FROM EMPLOYEES WHERE EMPID='e010';
```

Delete multiple rows matching a condition (deletes every row where `FIRSTNAME='sai'`, case-insensitive by default in MySQL):
```sql
DELETE FROM EMPLOYEES WHERE FIRSTNAME='sai';
```

TRUNCATE vs DROP

```sql
TRUNCATE TABLE EMPLOYEES;  -- removes ALL rows, keeps table structure
SELECT * FROM EMPLOYEES;   -- empty result

DROP TABLE EMPLOYEES;      -- removes the table entirely (structure + data)
```



 AUTO_INCREMENT Primary Key

```sql
CREATE TABLE EMPLOYEES(
    EMPID INT AUTO_INCREMENT PRIMARY KEY,
    NAME VARCHAR(100),
    DEPARTMENT VARCHAR(50)
);

INSERT INTO EMPLOYEES (NAME, DEPARTMENT)
VALUES
('MALLI', 'IT'),
('INDU', 'HR');
```

| EMPID | NAME | DEPARTMENT |
|---|---|---|
| 1 | MALLI | IT |
| 2 | INDU | HR |

`EMPID` auto-generates since no value was supplied for it.



 Creating a Table from a SELECT (Backup Tables)

```sql
CREATE TABLE BACKUPEMPLOYEES AS
SELECT * FROM EMPLOYEES;
```

```
DESC BACKUPEMPLOYEES;
+------------+--------------+------+-----+---------+-------+
| Field      | Type         | Null | Key | Default | Extra |
+------------+--------------+------+-----+---------+-------+
| EMPID      | int          | NO   |     | 0       |       |
| NAME       | varchar(100) | YES  |     | NULL    |       |
| DEPARTMENT | varchar(50)  | YES  |     | NULL    |       |
+------------+--------------+------+-----+---------+-------+
```

> Note: `CREATE TABLE ... AS SELECT` copies column names/types and data, but **not** constraints like `PRIMARY KEY` or `AUTO_INCREMENT` — the copied `EMPID` loses its key/auto-increment attributes.



 Generated (Computed) Columns

A generated column's value is computed automatically from other columns rather than being inserted directly.

```sql
CREATE TABLE PRODUCTS(
    PRODUCTID INT PRIMARY KEY,
    PRICE DECIMAL(10,2),
    QUANTITY INT,
    TOTALAMOUNT DECIMAL(10,2) GENERATED ALWAYS AS (PRICE * QUANTITY) STORED
);

INSERT INTO PRODUCTS (PRODUCTID, PRICE, QUANTITY)
VALUES
(1, 50, 3),
(2, 100.25, 6);
```

| PRODUCTID | PRICE | QUANTITY | TOTALAMOUNT |
|---|---|---|---|
| 1 | 50.00 | 3 | 150.00 |
| 2 | 100.25 | 6 | 601.50 |

`TOTALAMOUNT` recalculates automatically whenever `PRICE` or `QUANTITY` changes:
```sql
UPDATE PRODUCTS SET PRICE=500 WHERE PRODUCTID=1;
```

| PRODUCTID | PRICE | QUANTITY | TOTALAMOUNT |
|---|---|---|---|
| 1 | 500.00 | 3 | 1500.00 |
| 2 | 100.25 | 6 | 601.50 |

> `STORED` means the computed value is physically saved in the table (vs `VIRTUAL`, which recomputes it on every read without storing it).
